# 深蓝 · ABYSS

一个**单文件、零素材**的海底生存游戏。整片海洋——鱼、水母、光柱、焦散、海雪、礁石、气泡、声音——全部由代码在运行时生成。没有一张图片、一个字体文件或一段音频采样。

这不是一个"压体积"的 demo，而是沿用 24KB / 30KB 那一类小游戏的做法：**不加载资源，用算法把世界画出来**。

## 运行

`index.html` 是构建产物，可以直接双击打开，也可以起个静态服务：

```bash
python3 -m http.server 8000
# 打开 http://localhost:8000
```

运行时没有任何外部请求、没有依赖、没有图片。现代 Chrome / Safari / Firefox 均可。

## 开发

源码在 `src/` 下，用原生 ES 模块组织；`index.html` 由构建脚本把模块打包内联回单文件（这样双击依然可用，模块不会在 `file://` 下被 CORS 拦住）。

```bash
npm install          # 只装 esbuild（开发期依赖）
npm run watch        # 监听 src/ 改动，自动重建 index.html
npm run build        # 手动构建一次
npm run build:min    # 压缩版
```

因为产物是单文件、且不走任何 dev server 的注入，改完刷新浏览器即可。

### 目录结构

```
src/
  index.html          # HTML 外壳（CSS + DOM + 脚本占位符）
  main.js             # 装配 + 主循环，唯一知道"一帧做什么"的地方
  core/               # math / storage / dom / viewport / input
  config/             # species（物种表）· zones（深度色板）
  world/              # world（唯一可变状态）· spawn · audio · fx · ambient（鱼群/蝠鲼/热泉）
  systems/            # player / fish / jelly / plankton / camera / collision / hud / view
  render/             # background / creatures / ambient / fx / overlay / scene
  game/flow.js        # 状态机：菜单 → 游戏中 → 暂停 → 结算
tools/
  build.mjs           # esbuild 打包 + 内联进 HTML
  verify-equivalence.mjs  # 逐帧比对新旧渲染指令，证明重构零回归
  bench.mjs           # 纯逻辑性能基准
  mock-dom.mjs        # Node 里的 canvas / DOM 桩
test/                 # node:test 单测（纯函数 + 玩法规则）
```

### 校验

```bash
npm test        # 单测：数学、色板、生成、吞噬规则、摄像机、手感、环境元素、地形碰撞
npm run verify  # 等价性：新旧两版各跑 2000 帧，逐帧比对 canvas 指令与 DOM 写入
npm run bench   # 逻辑耗时基准
npm run check   # build + verify + test
```

`npm run verify` 是这次拆分的安全网：它把重构前的旧版和构建出的新版放进同一个沙箱，用假 canvas 录下每一次 2D context 调用（含坐标、颜色、混合模式），同时录下每一次 HUD 写入和 WebAudio 调用，逐帧比哈希。

覆盖范围：启动阶段（初始世界生成、HUD 初值）+ 桌面/触屏两套输入的 2000 帧，包含开始游戏 → 指针操控 → 吞噬成长 → 暂停恢复 → 静音 → 死亡 → 结算 → 回到海面 → 再潜入。

它比较的是 `HEAD` 里的 `index.html` 与当前构建产物，所以有两种用法：重构期间用它证明"画面和 DOM 一行没变"；改动视觉或玩法时它必然会报差异（这是预期的），改完提交后它会重新变绿，用作"构建产物和已提交源码一致"的检查。

## 操作

| 操作 | 键鼠 | 触屏 |
| --- | --- | --- |
| 游动 | 移动鼠标 / WASD | 手指拖动 |
| 加速 | 按住 空格 / 鼠标左键 | 按住屏幕 |
| 暂停 | Esc / P | — |
| 静音 | M 或右上角按钮 | 右上角按钮 |

目标：吞食浮游生物和小鱼成长，躲开更大的猎手，向更深处下潜。体型既是成长，也是生命——被咬会变小，太小就会被吞噬。

## 四层海

阳光带 → 暮光带 → 午夜带 → 深渊带。

水色、光照、鱼群密度、物种和危险程度随深度连续插值，没有硬切场景。越深越暗，生物开始发光，最后只剩生物光、海雪和巨型猎手的红眼。

## 全部是算出来的

- **鱼**：贝塞尔曲线身体、随速度摆动的尾鳍、背鳍/胸鳍、程序化条纹与斑点、眼睛、牙齿、鮟鱇的发光诱饵；每种鱼用 HSL 色相偏移做个体差异。
- **水母**：脉冲伞盖、波动的触须、边缘发光点、柔和的径向光晕。
- **礁石**：一维 value noise + fBm 生成的轮廓，分三层视差，边缘带微光。
- **光**：屏幕空间太阳与光晕、体积光柱、水面波纹、焦散线、水下漂浮颗粒。
- **声音**：WebAudio 实时合成——低频海洋底噪、进食、受伤、水层提示、死亡，没有任何音频文件。
- **生态**：按体型决定"能吃 / 被吃"；鱼会追逐、逃跑、互相分离、突袭、放弃追击；浮游生物自动补充。
- **自适应密度**：鱼、水母、浮游生物的数量按可视面积调整，桌面和手机都能保持合适的密度与性能。

## 海里的东西

除了鱼和水母，还有四种不参与"吃/被吃"的环境元素，按深度分工，让不同水层看起来不是同一种水：

| 元素 | 出现水层 | 说明 |
| --- | --- | --- |
| **海藻林** | 40m 以浅，170m 前完全消失 | 三层视差，叶片用贝塞尔画成带波浪边缘、随风摆动的长带 |
| **小鱼群** | 全水层 | 9~22 条极简小鱼组成的"云"，整体漂移、成员各自微摆 |
| **蝠鲼** | 全水层，远景剪影 | 翼展约为体长的 1.8 倍，翅膀有慢速拍动，半透明压在水色里 |
| **热泉** | 55m 以下 | 暖色喷口 + 上升烟柱 + 周期吐泡，气泡直接复用已有的气泡系统 |
| **珊瑚 / 海绵** | 全水层 | 附着在礁石和沉船上的扇形珊瑚与管状海绵，会轻微摇曳 |
| **礁石** | 全水层 | 实心障碍，由几个圆拼成，边缘不规则 |
| **裂缝** | 全水层 | 两块巨石夹出的窄缝，见下节 |
| **沉船残骸** | 70m 以下，稀有 | 断掉的船体 + 肋骨 + 桅杆，同样会挂珊瑚 |
| **螃蟹** | 全水层，礁石上 | 沿着石头上半弧爬行，到边缘折返 |
| **海龟** | 全水层 | 缓慢游动，四肢有划水动作 |

绘制上尽量合并：一个鱼群的所有成员合进同一条 path 只 `fill` 一次，海藻每层也只 `fill` 一次。
实测每帧 canvas 调用：加环境元素 +6%（浅水 3887 → 4121）、+3.3%（深水 4428 → 4576）；
再加地形与底栖生物后为浅水 4447、深水 4951。

顺带修了一个存量 bug：气泡原来只在 `y < -30`（接近水面）时回收，深水区永远升不到那个高度，
会无限累积。现在同时按"飘出视野上方"回收，并加了 160 个的硬上限。

## 障碍与躲避

礁石、裂缝和沉船都是**实心**的，玩家和鱼都会被挡住。地形统一用"一串圆"表示，碰撞就是圆vs圆，
命中后只消掉朝墙里的法向速度、保留切向速度——所以贴着石头游会顺着表面滑走，而不是被抵住。

裂缝（两块巨石之间的窄缝）是这个系统里唯一有玩法含义的结构：**缝宽固定 76px**。

- 玩家小的时候（外接直径 < 76）能钻进去，大猎手（直径 80+）进不来 → 洞穴是保命点
- 玩家长大了就钻不进去了，"体型既是成长也是生命"这条规则在这里多了一层代价

实现上踩过两个坑，都留在测试里防止回归：

- 一开始撞墙把 `vx`/`vy` 都乘 0.35，把切向速度也杀了，机器人顶着石头**20 秒挪不动**。
  改成法向投影后正常滑动。
- 推出迭代只做 2 轮时，石头夹角处收敛不了，被判成"一直碰撞"、速度反复清零，
  玩家直接冻住。迭代提到 6 轮后，推送后仍在几何体内的帧从 34.7% 降到 0.4%。
- 还有一次是地形顶部伸到水面之上，和"水面下界"夹出一个死角。现在地形生成后会整体下移，
  顶部至少离水面 185px。

对应的不变量测试：**朝任意方向游都能从石头里脱身**、**从水面出发一定能潜下去**。

## 水母会蜇人

水母原本只是免费食物，现在变成"风险/收益"型：

- 你比它大（`r > 水母r * 0.72`）→ 吃掉，加分
- 你比它小 → 被蜇：体型 ×0.94（被猎手咬是 ×0.855，所以轻得多）、击退、短暂无敌

所以小的时候要绕开水母，长大了才敢吃。

## 一些实现细节

- 深度色板在五个停靠点之间做 HSL 插值，避免换层时颜色跳变。
- 鱼的朝向用"水平镜像 + 俯仰角"实现，游向左时不会肚皮朝上。
- 发光一律用径向渐变或多次低透明度叠加，避免昂贵的 `shadowBlur`。
- 鱼的体积感用渐变画（背深腹浅），但渐变按"颜色桶"缓存复用——渐变坐标定义在单位空间里，
  绘制时被 CTM 变换到每条鱼身上，所以同色系的鱼共享同一个渐变对象，没有每帧新建的开销。
- 画布像素比封顶 1.5，兼顾 retinal 清晰度和填充率。
- 所有随机使用固定种子的 noise 或逐帧伪随机，礁石形状不会闪烁。
- 碰撞判定一律用平方距离，不开方。

## 手感与调参

所有会影响手感的数值集中在 `src/config/tuning.js`，改参数不用翻逻辑代码：玩家速度、巡游转向、
扑咬的前摇/冲刺/冷却、猎手生成距离与冷静期、同时追击上限。

调参前先用诊断脚本量一遍。这次针对"鱼来回摆动""敌人太凶"做的改动，实测数据：

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 巡游鱼掉头频率 | 0.35 次/秒（约 3 秒一次） | **0.06 次/秒**（约 17 秒一次） |
| 低速时朝向抖动 | 5.3% 的帧 | **0.2%** |
| 扑咬峰值速度 | 393 px/s | **268 px/s** |
| 260px 内有猎手的时间 | 86% | 48% |
| 机器人认真躲（120s，表层） | 被咬 30 次 | **被咬 10 次** |
| 机器人只顾吃不躲（表层） | 被咬 39 次 | 被咬 14.4 次 |
| 完全不动 | 13.9s 被吃 | 24s 被吃 |
| 机器人认真躲（120s，200m） | 10 次 | 被咬 11.2 次（比表层更危险） |

关键修复：

- **巡游不再每帧重算目标角**。原来把 `noise1()` 直接乘 `TAU*2` 当角度，噪声稍动就转几十度，鱼会原地画圈反复掉头。现在改成直线巡航 + 缓慢俯仰摆动，掉头是低频的显式决策。
- **朝向翻转加迟滞**。vx 穿零时立刻镜像会让鱼左右抖动，现在需要持续 0.22 秒且速度足够才翻。
- **扑咬拆成前摇 → 冲刺 → 冷却**。原来没有前摇、倍率 1.75，实测 393 px/s 比玩家常态还快，等于必被咬。现在前摇 0.28 秒（减速并亮红框提示），冲刺倍率 1.3。
- **同时追击的猎手最多 2 只**，扑咬结束后强制脱战 2.5~4.5 秒，避免被一圈猎手围殴。
- **猎手不会贴脸生成**。顺带修了一个边界 bug：原来先算安全距离、后把 y 夹到水面以下，玩家贴近水面时猎手会被夹到离玩家几像素处——等于贴脸刷怪。
- **猎手比例 20% → 14%**，新出生的猎手有 1.6 秒冷静期。
- **难度随深度梯度上升**。所有深度共用一套参数时，实测 200m 反而比表层更安全，等于"越深越没挑战"。
  现在追击上限（2→4）、追击半径（460→590）、追击与冲刺倍率、脱战时长都按 40m→220m 插值。

难度没有调没：站着不动 20 秒就被吃，只顾吃不躲照样挨咬，越深越危险。

## 性能

跑 `npm run bench` 得到的是**纯逻辑**耗时（30 鱼 / 137 浮游 / 4 水母）：

```
updateFish  (AI + 分离 + 回收)     0.0083 ms/frame
updateFoods / updateJellies        0.0039 ms/frame
updatePlayer + updateCamera        0.0003 ms/frame
reef silhouettes (fBm x3 层)       0.0026 ms/frame
合计                               0.0151 ms/frame   ← 60fps 预算的 0.09%
```

也就是说瓶颈不在 JS 计算，而在 canvas2d 的光栅化（填充率）。这也是这个项目**不需要 WASM** 的原因：逻辑本身只占预算的千分之一，改用 Rust/Go 只能拿回这一点点，而光栅化发生在浏览器内部，WASM 碰不到。

真要提性能，方向是减少绘制开销，按性价比排序：

1. 把鱼/水母按尾摆相位预烘成 sprite，绘制时只 `drawImage`（省掉每条鱼的路径构建、`clip()` 与渐变创建）。
2. 浮游生物和粒子按颜色归并成一条 path，一次 `fill`。
3. 渐变对象按深度取整复用；礁石层缓存到离屏画布。
4. 帧超预算时降 DPR（1.5 → 1.0 → 0.75），做自适应分辨率。
